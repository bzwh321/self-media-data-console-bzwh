# self-media-console-director

## 目标

把服务器采集来的自媒体数据变成每天可看的本地经营工作台，并把当天结论和截图发到飞书。

## 默认判断

- 如果服务器同步失败，日报状态为 `failed`。
- 如果有平台数据过期，日报状态为 `partial`。
- 如果业务校验失败，日报状态为 `failed`。
- 如果同步、规范化、校验都通过，日报状态为 `ready`。

## 运行阶段

| 阶段 | 说明 | 失败处理 |
| --- | --- | --- |
| `sync_server` | 拉取服务器采集结果 | 记录失败原因，停止正常日报 |
| `normalize` | 生成统一数据契约 | 记录脚本 stderr 和缺失文件 |
| `validate_accuracy` | 校验平台、日期、新鲜度、核心指标 | 标出缺失平台和异常指标 |
| `build_workbench` | 生成本地工作台 HTML | 不影响数据，但影响截图发送 |
| `capture_screenshot` | 截取工作台首页 | 截图失败时仍可发文字 |
| `send_lark` | 发送文字结论和截图 | 记录飞书发送结果 |

## 文本结论规则

日报文本使用固定模板，不由 AI 自由改写。模板至少包含：

- 今日状态：`ready`、`partial` 或 `failed`
- 数据日期范围
- 各平台采集新鲜度
- 核心指标：总粉丝、新增粉丝、收入、发布数、播放或阅读、互动
- 异常说明：服务器不可达、平台数据过期、字段缺失、校验失败
- 后续处理：需要人工重新登录、检查服务器任务或调整字段映射

## 数据准确性规则

- 平台集合应覆盖小红书、抖音、知乎、B站、公众号；知识星球收入可作为扩展平台接入。
- `dateMax` 应接近当天或昨天，具体阈值由平台采集更新时间决定。
- 总粉丝取结束日前最新快照，不按日期范围求和。
- 收入只统计有可靠来源的平台，小红书和 B站优先。
- 内容类数据保留快照历史，不覆盖原始采集文件。

## 飞书发送规则

- 正常日报发给指定联系人或群。
- 部分失败时仍发送，但标题必须说明“部分平台未更新”。
- 全链路失败时只发送异常摘要，不发送经营结论。
- 截图作为附件发送；如果附件失败，文本里保留本地截图路径和失败原因。
