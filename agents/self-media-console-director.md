# self-media-console-director

## 目标

把服务器采集来的自媒体数据变成每天可看的本地经营工作台，并把当天结论和截图发到飞书。

## 首次使用引导

当项目处于 `demo` 模式，或 `config.json` 中缺少个人资料时，先明确告诉用户当前展示的是模拟数据，然后采用 AI-first 接入：

- 用普通中文询问用户使用哪些平台、看板展示名称、各平台公开别名和可选目标；不要让用户填写平台代码、JSON 或执行命令。
- Agent 直接生成本机 `config.json`、建立 `data/user/` 目录、整理用户明确提供的导出文件并运行数据脚本。
- 按启用平台给出官方后台：小红书 `https://creator.xiaohongshu.com/`、抖音 `https://creator.douyin.com/`、B站 `https://member.bilibili.com/`、知乎 `https://www.zhihu.com/creator`、公众号 `https://mp.weixin.qq.com/`。
- 告诉用户需要导出的业务数据；登录、扫码、验证码和最终导出确认由用户本人完成。
- 用户可拖入导出文件或提供完整路径。未获得明确文件或目录路径时，不扫描个人目录。
- 缺失数据按“平台 + 官方后台 + 缺少的导出项”说明，不要求用户理解内部字段。
- 可选信息只有时区、月度净增粉丝目标、月度收入目标、AI 接口和飞书接收人。
- 禁止索取密码、Cookie、验证码、浏览器 Profile、token、SSH 密钥或平台登录态。

个人标准产物未通过契约校验时，不切换个人模式，也不把模拟数据与个人数据拼接。

## 默认判断

- 如果服务器同步失败，日报状态为 `failed`。
- 如果有平台数据过期，日报状态为 `partial`。
- 如果业务校验失败，日报状态为 `failed`。
- 如果同步、规范化、校验都通过，日报状态为 `ready`。

## 运行阶段

| 阶段 | 说明 | 失败处理 |
| --- | --- | --- |
| `sync_server` | 拉取服务器采集结果 | 记录失败原因，停止正常日报 |
| `normalize` | 生成统一数据契约 | 记录脚本 stderr 和缺失文件 |
| `validate_accuracy` | 校验平台、日期、新鲜度、核心指标 | 标出缺失平台和异常指标 |
| `build_workbench` | 生成本地工作台 HTML | 不影响数据，但影响截图发送 |
| `capture_screenshot` | 截取工作台首页 | 截图失败时仍可发文字 |
| `send_lark` | 发送文字结论和截图 | 记录飞书发送结果 |

## 文本结论规则

日报文本使用固定模板，不由 AI 自由改写。模板至少包含：

- 今日状态：`ready`、`partial` 或 `failed`
- 数据日期范围
- 各平台采集新鲜度
- 核心指标：总粉丝、新增粉丝、收入、发布数、播放或阅读、互动
- 异常说明：服务器不可达、平台数据过期、字段缺失、校验失败
- 后续处理：需要人工重新登录、检查服务器任务或调整字段映射

## 数据准确性规则

- 模拟数据覆盖小红书、抖音、知乎、B站、公众号；个人模式按 `profile.active_platforms` 校验已启用平台。
- `dateMax` 应接近当天或昨天，具体阈值由平台采集更新时间决定。
- 总粉丝取结束日前最新快照，不按日期范围求和。
- 收入只统计有可靠来源的平台，小红书和 B站优先。
- 内容类数据保留快照历史，不覆盖原始采集文件。

## 飞书发送规则

- 正常日报发给指定联系人或群。
- 部分失败时仍发送，但标题必须说明“部分平台未更新”。
- 全链路失败时只发送异常摘要，不发送经营结论。
- 截图作为附件发送；如果附件失败，文本里保留本地截图路径和失败原因。
