# 数据目录结构说明

本项目使用两个互不混合的数据根：`data/demo` 保存可公开的模拟数据，`data/user` 保存本机个人数据。当前支持小红书、抖音、知乎、B站和公众号。

## 根目录

```text
data/{demo|user}/
├── B站数据/
├── 抖音数据/
├── 知乎数据/
├── 公众号数据/
├── 小红书内容数据/
├── 小红书电商数据/
├── 小红书推广数据/
├── hotlist/normalized/
└── dashboard-normalized/
```

平台账号目录遵循：

```text
{平台数据}/{账号别名}/raw/{数据类型}/YYYY-MM/
{平台数据}/{账号别名}/monthly/{数据类型}/
```

各平台下的 `服务器同步/` 子目录可保存从远程服务器拉回的同类数据版本，但不是必需项。

## 融合规则

1. 按去掉 `服务器同步` 后的逻辑相对路径分组。
2. 同一逻辑文件只选择最新版；更新时间相同时优先服务器同步版。
3. 账号识别忽略 `服务器同步` 路径段。
4. 内容数据先保留全量明细，再生成平台/账号最新快照。
5. 所有标准表保留相对 `source_file` 和 `source_mtime`。

## 小红书粉丝增长

每日粉丝增长只使用创作者中心 `账号概览 → 涨粉数据 → 近30日 → 导出数据` 的日粒度导出，不通过总粉丝快照反推，也不均摊：

```text
小红书内容数据/{账号别名}/raw/account_follower_growth/YYYY-MM/
小红书内容数据/{账号别名}/monthly/account_follower_growth/
```

误采的非粉丝类文件应放入 `_invalid/`，不能混入正确目录。

## 标准产物

`dashboard-normalized/` 由 Python 脚本生成，不手工修改：

- `self_media_daily_metrics.csv`
- `self_media_platform_snapshots.csv`
- `self_media_content_detail.csv`
- `self_media_content_items.csv`

- `self_media_summary.json`
- `self_media_metric_check.md`
- `compact_dashboard_data.json`
- `latest_business_check.json`

## 刷新个人数据

在 `config.json` 中设置：

```json
{
  "data": {"mode": "user", "root": ""}
}
```

然后运行：

```powershell
python scripts\normalize-self-media-dashboard.py
python scripts\check-self-media-dashboard-contract.py --console-root .
python scripts\build_compact_dashboard.py
```

也可以继续使用 `SELF_MEDIA_DATA_ROOT` 指向外部授权数据目录；该环境变量优先级最高。
