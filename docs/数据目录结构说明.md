# 数据目录结构说明

本文件说明数据根目录的组织方式、融合规则和验收流程。详细采集方法见 `数据采集指南.md`，字段映射见 `自媒体看板字段映射对照表.md`。

## 目录结构

```
{DATA_ROOT}/
├── B站数据/                    # 各平台原始与月度数据
├── 抖音数据/
├── 知乎数据/
├── 公众号数据/
├── 小红书内容数据/
├── 小红书电商数据/
├── 小红书推广数据/
├── dashboard-normalized/       # 融合后给中控台读取的标准数据
├── scripts/                    # 数据处理脚本
│   ├── normalize-self-media-dashboard.py
│   └── check-self-media-dashboard-contract.py
└── 自媒体看板字段映射对照表.md
```

各平台下的 `服务器同步/` 子目录用于存放从远程服务器拉取的数据版本（可选）。

## 融合规则

融合脚本（`normalize-self-media-dashboard.py`）会同时读取本地原有数据和 `服务器同步` 目录的数据：

1. **文件分组**：按"去掉 `服务器同步` 后的逻辑相对路径"分组。
2. **版本选择**：同一逻辑文件只保留最新版本；更新时间相同时，优先使用服务器同步版本。
3. **账号识别**：忽略 `服务器同步` 路径段，避免误判为账号名。
4. **内容聚合**：先保留全量明细，再按平台/账号聚合最新快照给看板。
5. **数据溯源**：所有标准表保留 `source_file` 和 `source_mtime` 字段。

## 小红书粉丝增长口径

小红书每日粉丝增长只使用创作者中心 `账号概览 → 涨粉数据 → 近30日 → 导出数据` 的真实日粒度导出，不使用总粉丝快照反推，也不做日期均摊。

- 原始目录：`小红书内容数据/{账号名}/raw/account_follower_growth/YYYY-MM/`
- 月度目录：`小红书内容数据/{账号名}/monthly/account_follower_growth/`
- 有效 raw 文件应包含 `净涨粉趋势`、`新增关注趋势`、`取消关注趋势` 等 sheet
- 误采到非粉丝类文件时，应放入 `_invalid/` 目录，不能混在正确目录中

## 如何刷新融合数据

```powershell
# 设置数据根目录（如不使用默认的 sample-data）
$env:SELF_MEDIA_DATA_ROOT = "D:\your-data-root"

# 运行归一化脚本
python scripts/normalize-self-media-dashboard.py

# 运行契约校验
python scripts/check-self-media-dashboard-contract.py

# 派生看板紧凑数据
python scripts/build_compact_dashboard.py
```

成功后会刷新 `dashboard-normalized/` 下的所有文件：

- `self_media_daily_metrics.csv` — 每日指标
- `self_media_platform_snapshots.csv` — 平台快照
- `self_media_content_detail.csv` — 全量内容明细
- `self_media_content_items.csv` — 最新内容快照
- `self_media_dashboard.json` — 主看板数据
- `self_media_summary.json` — 汇总信息
- `self_media_metric_check.md` — 指标校验报告

## 读取优先级

1. 优先读取 `monthly/*` 规范化文件；缺失时才回退读取 `raw/*`。
2. 同一平台同一指标有多个来源时，以字段映射对照表的"优先来源"为准。
3. 总粉丝类指标按筛选结束日期取最新快照，不按日期范围求和。
4. 粉丝增长类指标按日期范围求和；负值保留。
5. `source_file` 和 `source_mtime` 必须随每条记录保留。

## 注意事项

- 不要手工修改 `dashboard-normalized/` 下的融合产物；应修改源数据或脚本后重跑。
- `self_media_content_detail.csv` 是全量内容明细；`self_media_content_items.csv` 是看板使用的最新快照。
- `self_media_summary.json` 里的 `source_counts.file_fusion` 可检查本地与服务器版本的融合情况。
- 每次采集新数据后，先运行 normalize 脚本刷新，再运行 build_compact_dashboard 派生看板数据。
