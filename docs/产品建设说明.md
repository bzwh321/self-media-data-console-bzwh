# 产品建设说明

## 产品目标

自媒体数据中控台面向单人经营场景，帮助用户每天知道各平台数据是否更新、经营表现是否变化、哪些内容值得继续投入、哪些平台需要处理登录态或采集异常。

它不是一个临时脚本集合，而是一个可以每天固定打开、固定发送、固定追溯的本地产品。

## 产品形态

第一版采用本地 HTML 工作台，而不是直接复用现有看板的 Electron 页面。这样可以减少耦合，也方便截图和飞书发送。

工作台包含四个核心区域：

| 区域 | 内容 |
| --- | --- |
| 经营总览 | 总粉丝、新增粉丝、收入、发布数、播放或阅读、互动 |
| 平台状态 | 小红书、抖音、知乎、B站、公众号的采集新鲜度和异常 |
| 内容表现 | Top 内容、异常内容、互动率变化 |
| 数据说明 | 口径、来源文件、同步时间、校验结果 |

## 非 AI 化边界

日常结论由规则生成。规则可以持续迭代，但默认不调用大模型。

适合规则生成的结论：

- 哪个平台未更新。
- 哪个平台新增粉丝最高。
- 哪个平台收入为 0 或异常。
- 哪篇内容播放或互动最高。
- 哪些数据超过新鲜度阈值。

适合人工或 AI 辅助的场景：

- 平台字段变化后重新识别口径。
- 月度复盘或专题分析。
- 看板设计改版。
- 异常原因需要结合截图和日志判断。

## 第一版页面

第一版页面只服务日报截图和本地查看，不追求完整后台管理。页面应满足：

- 打开即展示最新数据。
- 顶部明确显示日报状态。
- 异常平台用明显但克制的样式标出。
- 所有关键指标能追溯到数据日期。
- 页面适合截取一张 16:9 总览图发飞书。

## 后续扩展

- 增加趋势筛选和平台下钻。
- 增加内容设计稿与内容表现关联。
- 增加收入、粉丝、内容发布的月度视图。
- 增加飞书群内交互命令，例如“发今日自媒体日报”“查看异常平台”。
