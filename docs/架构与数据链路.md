# 架构与数据链路

## 总体链路

```text
服务器采集任务
  ↓
服务器数据目录
  ↓
sync-server-self-media-dashboard.py
  ↓
<DATA_ROOT>\各平台\服务器同步
  ↓
normalize-self-media-dashboard.py
  ↓
dashboard-normalized\self_media_dashboard.json
  ↓
自媒体数据中控台本地工作台
  ↓
截图 + 文字结论
  ↓
飞书
```

## 本项目职责

本项目从“服务器同步”开始接管，不改变服务器采集脚本的站点操作逻辑。

| 层级 | 文件或目录 | 说明 |
| --- | --- | --- |
| 同步层 | `sync-server-self-media-dashboard.py` | 拉取服务器采集结果 |
| 规范化层 | `normalize-self-media-dashboard.py` | 统一平台字段 |
| 校验层 | `check-self-media-dashboard-contract.py` | 判断核心指标和业务契约是否成立 |
| 工作台层 | 本项目生成的 HTML | 产品化展示 |
| 推送层 | Lark 插件或 `lark-cli` | 发送文字和截图 |

## 准确性反馈

每天必须生成一份运行记录，记录以下内容：

| 字段 | 说明 |
| --- | --- |
| `run_date` | 本次运行日期 |
| `status` | `ready`、`partial`、`failed` |
| `sync_status` | 服务器同步状态 |
| `normalized_status` | 规范化状态 |
| `validation_status` | 校验状态 |
| `platform_freshness` | 各平台最新日期和过期天数 |
| `missing_platforms` | 缺失或未更新的平台 |
| `report_path` | Markdown 报告路径 |
| `screenshot_path` | 截图路径 |
| `lark_send_status` | 飞书发送状态 |

## 数据新鲜度

不同平台更新时间不同，不能简单要求所有平台当天更新。第一版采用默认阈值：

| 平台 | 默认要求 |
| --- | --- |
| 小红书 | 允许 T-1 |
| 抖音 | 允许 T-1 |
| 知乎 | 允许 T-1 |
| B站 | 允许 T-1 |
| 公众号 | 允许 T-1 |
| 知识星球 | 允许 T-1 |

如果平台后台天然延迟，可在配置里单独放宽。

## 本地工作台

工作台应直接读取 `self_media_dashboard.json` 和每日运行记录。它不直接读原始 Excel 或 CSV，避免页面层重复实现口径。

截图由工作台页面生成，默认保存到：

`<PROJECT_ROOT>\runtime-data\screenshots`
