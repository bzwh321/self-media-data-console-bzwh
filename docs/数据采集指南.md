# 数据采集指南

本指南说明如何从各平台创作者后台手动导出数据，以及如何按本项目的目录约定存放，最终通过 `normalize-self-media-dashboard.py` 脚本归一化为看板数据。

## 整体链路

```
各平台创作者后台 → 手动导出 CSV/XLSX/JSON → 按目录约定存放 → normalize 脚本 → dashboard-normalized/ → 中控台看板
```

## 数据根目录

所有个人平台数据默认存放在项目 `data/user/`。先复制 `config.example.json` 为 `config.json`，并设置：

```json
{
  "data": {"mode": "user", "root": ""}
}
```

如果不设置，默认使用项目内的 `data/demo` 模拟数据。高级用户仍可用 `SELF_MEDIA_DATA_ROOT` 指向外部授权目录。

## 目录结构约定

```
{DATA_ROOT}/
├── B站数据/
│   ├── {账号名}/
│   │   ├── raw/{数据类型}/YYYY-MM/      # 原始导出文件
│   │   ├── monthly/{数据类型}/           # 月度汇总
│   │   └── history/                      # 历史归档
│   └── 服务器同步/{账号名}/              # 服务器拉取版本（可选）
│       ├── raw/{数据类型}/
│       └── monthly/{数据类型}/
├── 抖音数据/
├── 知乎数据/
├── 公众号数据/
├── 小红书内容数据/
├── 小红书电商数据/
├── 小红书推广数据/
├── dashboard-normalized/                 # normalize 脚本输出
└── scripts/                              # 数据处理脚本
```

### 目录约定规则

- 每个平台一个顶级目录，目录名以"数据"结尾（如 `B站数据`、`抖音数据`）
- 每个账号一个子目录，账号名自定义
- `raw/` 存放原始导出文件，按 `YYYY-MM` 月份分文件夹
- `monthly/` 存放月度汇总文件
- `服务器同步/` 是可选的，用于存放从远程服务器拉取的版本
- 同一天多次同步的文件用 `_HHMMSS` 时间戳后缀区分
- normalize 脚本会优先读取 `monthly/`，缺失时回退到 `raw/`
- 同一逻辑文件只保留最新版本

## 各平台采集方法

### 1. 小红书

**后台入口：** https://creator.xiaohongshu.com

**需要导出的数据：**

| 数据类型 | 路径 | 文件格式 | 说明 |
|----------|------|----------|------|
| 账号概览 | 创作者中心 → 账号概览 → 导出 | .xlsx | 近30日观看量、曝光量、粉丝数据 |
| 粉丝快照 | 创作者中心 → 涨粉数据 → 导出 | .xlsx | 每日新增粉丝、流失粉丝、总粉丝 |
| 内容分析 | 创作者中心 → 内容分析 → 导出 | .xlsx | 笔记标题、观看量、曝光、点赞、评论、收藏、分享、涨粉 |
| 粉丝增长 | 创作者中心 → 涨粉数据 → 近30日 → 导出 | .xlsx | 净涨粉趋势、新增关注趋势、取消关注趋势 |

**目录约定：**

```
小红书内容数据/{账号名}/
  raw/
    account_overview/YYYY-MM/     # 账号概览
    fans_snapshot/YYYY-MM/        # 粉丝快照
    content_analysis/YYYY-MM/     # 内容分析
    account_follower_growth/YYYY-MM/  # 粉丝增长
  monthly/
    account_overview/
    fans_snapshot/
    content_analysis/
    account_follower_growth/
```

**电商数据（如有店铺）：**

```
小红书电商数据/{店铺名}/
  raw/
    datacenter_overview/YYYY-MM/  # 商家经营核心数据（支付金额、退款金额）
```

**粉丝增长口径：** 只使用创作者中心"涨粉数据→近30日→导出数据"的真实日粒度导出，不使用总粉丝快照反推。

```
  raw/

    content_list/YYYY-MM/     # 作品分析

    operation/
    content_list/
    content_analysis/
```

### 3. B站

|----------|------|----------|------|

| 博主日常数据 | 创作中心 → 数据中心 → 播放数据 → 导出 | .xlsx/.csv | 日期、播放量、点赞、评论、收藏、分享、硬币、弹幕 |
| 商品销售数据 | 创作中心 → 数据中心 → 商品销售 → 导出 | .xlsx | 下单时间、实际成交金额 |

**目录约定：**

```
B站数据/{账号名}/
  raw/
    粉丝数据/YYYY-MM/         # 粉丝数据

    商品销售数据/YYYY-MM/     # 商品销售

  monthly/

    商品销售数据/
```

### 4. 知乎

**后台入口：** https://www.zhihu.com/creator

**需要导出的数据：**

| 数据类型 | 路径 | 文件格式 | 说明 |
|----------|------|----------|------|
| 关注者数据 | 创作者中心 → 数据分析 → 关注者 → 导出 | .xls | 日期、关注者总数、关注者变化 |
| 内容数据 | 创作者中心 → 数据分析 → 内容 → 导出 | .xls | 日期、阅读、播放、点赞、喜欢、评论、收藏、分享 |

**目录约定：**

```
知乎数据/{账号名}/
  raw/

```

### 5. 公众号

**后台入口：** https://mp.weixin.qq.com

**需要导出的数据：**

| 数据类型 | 路径 | 文件格式 | 说明 |
|----------|------|----------|------|
| 用户统计 | 统计 → 用户分析 → 导出 | .csv/.json | date、total_followers、net_increase、unfollowed |
| 内容统计 | 统计 → 内容分析 → 导出 | .csv | date、article_count、reads、shares、comments |

**目录约定：**

```
公众号数据/{账号名}/
  user_stats/YYYY-MM.csv       # 用户统计
  content_stats/YYYY-MM.csv    # 内容统计
  article_stats/YYYY-MM.csv    # 文章统计
```

公众号的 `服务器同步/` 目录按日期文件夹 `YYYY-MM-DD` 归档，每天含 `history.json` 和 `user_stats.json`。

## 数据归一化

### 运行 normalize 脚本

将各平台原始数据按上述目录约定存放后，执行：

```powershell
python scripts/normalize-self-media-dashboard.py
```

脚本会读取 `{DATA_ROOT}` 下所有平台数据，融合归一化后输出到 `{DATA_ROOT}/dashboard-normalized/`：

| 输出文件 | 说明 |
|----------|------|
| `self_media_dashboard.json` | 主看板数据（平台摘要、日指标、内容Top） |
| `self_media_daily_metrics.csv` | 每日指标明细 |
| `self_media_platform_snapshots.csv` | 平台粉丝快照 |
| `self_media_content_detail.csv` | 全量内容明细 |
| `self_media_content_items.csv` | 最新内容快照 |
| `self_media_summary.json` | 汇总信息 |
| `self_media_metric_check.md` | 指标校验报告 |

### 运行契约校验

```powershell
python scripts/check-self-media-dashboard-contract.py --console-root .
```

校验数据完整性和一致性，生成 `latest_business_check.json`。

### 派生看板紧凑数据

```powershell
python scripts/build_compact_dashboard.py
```

从 `self_media_dashboard.json` 派生 `compact_dashboard_data.json`（前端直接消费的紧凑格式）。

## 依赖

```powershell
pip install -r requirements.txt
```

normalize 脚本依赖 `pandas` 和 `openpyxl`，契约校验仅需标准库。

## 采集频率建议

- 粉丝数据：每日一次
- 内容数据：每周至少一次
- 收入数据：每月一次（或按平台导出周期）
- normalize 脚本：每次采集后运行一次
