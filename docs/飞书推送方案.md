# 飞书推送方案

## 推送内容

飞书每天收到两类内容：

1. 文字结论：用固定模板生成，说明状态、核心指标、异常平台和处理建议。
2. 看板截图：截取本地中控台首页，作为当天经营概览图。截图直接来自 `console/index.html` 的真实页面渲染，并启用打印/截图样式，隐藏按钮、弹窗等交互控件，保证飞书图片和本地中控台排版一致。

## 消息结构

```text
标题：自媒体数据日报 YYYY-MM-DD
状态：ready / partial / failed
数据区间：YYYY-MM-DD 至 YYYY-MM-DD

核心指标：
- 总粉丝
- 新增粉丝
- 收入
- 发布数
- 播放或阅读
- 互动

平台状态：
- 小红书：正常 / 过期 / 缺失
- 抖音：正常 / 过期 / 缺失
- 知乎：正常 / 过期 / 缺失
- B站：正常 / 过期 / 缺失
- 公众号：正常 / 过期 / 缺失

今日结论：
- 由固定规则生成，不调用 AI

异常处理：
- 如有异常，给出对应路径和原因
```

## 接收对象

第一版默认支持两种接收方式：

| 类型 | 参数 |
| --- | --- |
| 联系人 | `open_id` 或姓名解析结果 |
| 群聊 | `chat_id` |

为了避免误发，正式定时前应先发送到个人联系人验证。

本项目通过 `config.json` 配置收件人，不在代码中写死联系人，也不保存飞书 token：

```json
{
  "lark": {
    "recipients": [
      { "type": "user", "name": "日报接收人", "open_id": "ou_xxxxxxxxxxxxxxxxx" },
      { "type": "chat", "name": "自媒体日报群", "chat_id": "oc_xxxxxxxxxxxxxxxxx" }
    ]
  }
}
```

`send-lark` 阶段使用本机已授权的 `lark-cli` 发送；如未配置 `lark.recipients`，流水线只记录 `skipped`，不会发送到任何人。

## 截图发送

截图保存到本项目 `runtime-data\<mode>\screenshots`，命名为 `daily-console-YYYY-MM-DD.png`。发送飞书时先发送 Markdown 正文，再发送中控台截图图片；如果图片发送失败，文字消息仍保留，并在运行记录中写入失败原因。

## 失败处理

- 飞书文字发送失败：记录错误，不删除日报和截图。
- 截图发送失败：仍发送文字，文本里写明截图路径。
- 全链路失败：发送失败摘要，不发送经营判断。

运行记录写入 `runtime-data\<mode>\logs\daily-run-YYYY-MM-DD.json`，关键字段包括：

- `screenshot_status`：截图是否成功。
- `screenshot_path` / `report_image_path`：飞书日报图片路径。
- `lark_send_status`：`success`、`partial_failed`、`failed` 或 `skipped`。
- `lark_results`：每个收件人的文本和图片发送结果。
