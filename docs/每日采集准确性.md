# 每日采集准确性

## 判断目标

每天不只要知道“脚本是否跑完”，还要知道“今天的数据能不能信”。准确性反馈应进入本地工作台，也应进入飞书日报。

## 状态分级

| 状态 | 含义 | 飞书表达 |
| --- | --- | --- |
| `ready` | 同步、规范化、校验全部通过 | 今日自媒体数据已更新 |
| `partial` | 主链路完成，但部分平台过期或缺字段 | 今日自媒体数据部分平台未更新 |
| `failed` | 同步、规范化或校验失败 | 今日自媒体数据生成失败 |

## 每日检查项

| 类型 | 判断方式 |
| --- | --- |
| 服务器同步 | `server_sync_refresh_report.json` 中状态为 success |
| 平台覆盖 | 看板平台集合包含预期平台 |
| 数据日期 | `dateMax` 和各平台 `latestDailyDate` 未超过阈值 |
| 核心指标 | 总粉丝、新增粉丝、收入、发布数不出现明显空值 |
| 业务契约 | `latest_business_check.json` 状态为 ready |
| 来源追溯 | 关键数据保留 `source_file` 或同步来源 |

## 异常表达

异常不能被日报结论掩盖。飞书文本应直接写清：

- 哪个平台没更新。
- 最后更新时间是哪一天。
- 可能原因来自服务器同步、平台登录态、字段变化还是原始文件缺失。
- 需要人工处理时，说明应该检查哪个目录或哪个站点登录态。

## 保留记录

每日运行记录保存到：

`<PROJECT_ROOT>\runtime-data\logs`

文件名建议：

`daily-run-YYYY-MM-DD.json`
